# Codebase Audit & Implementation Plan — October 2026

Scope: the whole repository (`frontend/`, `backend/`, `deploy/`, docs), reviewed for bugs, security issues, deployment problems and missing features. Fixes are on branch `claude/vibrant-ritchie-tg7ptv`. **Nothing was deployed and no server was touched**; changes under `deploy/` only take effect the next time someone runs those scripts.

Severity: **Critical** = remotely exploitable or breaks the core purpose of the site · **High** = real security or reliability impact · **Medium** = incorrect behaviour with a workaround · **Low** = hygiene.

## 1. Findings fixed in this branch

| # | Sev. | Area | Finding | Fix |
|---|---|---|---|---|
| 1 | Critical | Dependencies | `next@15.5.22` had unauthenticated RCE advisories in the Image Optimization API (AVIF and SVG), and `next.config.ts` enables AVIF. It also had SSG/ISR cache poisoning and a Server Actions DoS. | `next`, `eslint-config-next`, `@next/third-parties` → `15.5.28` (15.x backport line, no major upgrade). |
| 2 | Critical | Rate limiting | Django only ever sees the Next.js server (`127.0.0.1`), so **every visitor shared one throttle bucket**: 10 submissions per hour across all four forms for the whole site. Anyone could block lead capture with 10 requests, and 20 bad logins locked every admin out. | Route Handlers forward the visitor IP (`src/lib/client-ip.ts`); Django trusts one proxy hop (`NUM_PROXIES=1`). Verified end-to-end through both servers. |
| 3 | High | Rate limiting | Throttle counters lived in per-process `LocMemCache`, so with 3 Gunicorn workers the real limit was about 3× the setting and varied by worker. | Shared `FileBasedCache` (no new service or migration). |
| 4 | High | Admin login | Dedicated per-IP `login` throttle (10/hour) added, separate from the general anonymous budget. | `accounts/views.py`. |
| 5 | High | Admin login | **Open redirect**: after sign-in, `?redirect=` went straight to `router.push()`, so `/admin/login?redirect=https://evil.example` sent a freshly signed-in admin off-site. | `safeAdminRedirect()` allows only same-origin `/admin` paths. |
| 6 | High | Dependencies | `jspdf@2.5.2`: critical path-traversal and HTML-injection advisories, plus a vulnerable bundled DOMPurify. `sharp`/libvips, `postcss`, `nanoid`, `source-map-js` also had advisories. `djangorestframework@3.17.2` had 3 CVEs. | `jspdf@4.2.1`, `npm audit fix`, DRF `3.18.2`. Remaining advisories are listed in §3. |
| 7 | High | Settings | `DJANGO_DEBUG` defaulted to **true**, and `SECRET_KEY` silently fell back to a public dev value that signs the admin JWTs. | DEBUG defaults to false; settings refuse to load with DEBUG off and a placeholder or short key. |
| 8 | High | Admin reply | A failed email send still returned success **and marked the lead "replied"**, so it left the "new" queue while the customer never heard back. | `send_reply` returns a status; the view returns 502 and leaves the status unchanged on failure. |

| 12 | Medium | Admin reply | Recipient and subject were not validated (multi-line subjects, non-emails), and an unknown submission id was ignored silently. | Email and single-line subject validation; 404 for a missing submission. |
| 13 | Medium | Session | A refresh token was set as a 14-day cookie but nothing ever used it. | No longer issued; logout still clears old ones. |
| 14 | Medium | Dashboard | An invalid or expired token left "Not authorized." on every panel with no way back. | Query/mutation 401/403 redirects to sign-in. |
| 15 | Medium | Deploy | `enable-tls.sh` called an undefined `die()`. | Defined. |
| 16 | Medium | Deploy | `deploy.sh` copied the live SQLite file with `cp` while Gunicorn was serving (risks a corrupt backup), and backups were never pruned on a disk shared with other sites. | sqlite3 online-backup API; keep the newest 20. |
| 17 | Medium | Deploy | `npm ci --omit=dev` cannot build (`next build` needs TypeScript/Tailwind/PostCSS from devDependencies). It only worked because husky's failure tripped the fallback. | One full `npm ci` with `HUSKY=0`. |
| 18 | Medium | Tests | The 3 gallery e2e tests were already failing on `main`: they clicked a "Gallery" tab that `7b5001a` removed. | Spec targets the grid by test id. |
| 19 | Medium | CI | No CI at all, so nothing stopped a red build or a vulnerable dependency reaching `main`. | `.github/workflows/ci.yml`: Django check/migrations/tests/pip-audit; Next lint/typecheck/tests/build/npm audit (critical). No deploy step. |
| 20 | Low | Backend | Successful notification sends (INFO) were never logged, so the journal could not confirm a lead email went out. Deprecated `.extra()` was used for date grouping. | `LOGGING` for `leads.*`; `TruncDate`. |

### Checked and found sound

Email bodies HTML-escape all user input · CSV export defuses formula injection · honeypot is checked on both layers · admin cookie is `httpOnly`/`Secure`/`SameSite=Lax` · CORS is not `*` · Django and Next bind to loopback · systemd units are sandboxed · nginx keeps the ACME path on HTTP and redirects `www` → apex · `manage.py check --deploy` warnings (`SECURE_SSL_REDIRECT`, HSTS, secure cookies) do not apply because TLS ends at nginx and Next.js sends HSTS.

## 3. Recommended follow-ups — need your decision or approval

These are out of scope for this branch: they change the production deploy flow, need a business decision, or are larger pieces of work.

1. ~~**Deploy causes a short outage on every run.**~~ **Fixed in a follow-up PR:** builds now alternate between `.next-blue` and `.next-green`, so the live directory is never rebuilt in place. Measured locally, the old in-place build failed 411 of 1,704 asset requests while it ran; the slot build failed 0 of 1,704. See `deploy/README.md` → Routine deploys.
2. **No session revocation.** Access tokens last 8 hours and logout only deletes the cookie, so a stolen token stays valid until it expires. Options: shorten the lifetime and add refresh, or enable SimpleJWT's token blacklist.
3. **HSTS `preload; includeSubDomains`** (`next.config.ts`) commits `mudhotech.com` and *every* subdomain to HTTPS-only, permanently once it is submitted to the preload list. Confirm that every current and future subdomain (mail, webmail, etc.) will serve valid TLS, or drop `preload`.
4. **CSP still allows `'unsafe-inline'` and `'unsafe-eval'`** for scripts. A nonce-based CSP would remove most of the XSS impact.
5. **Newsletter has no double opt-in or unsubscribe.** `confirmed` is never set and there is no way to leave the list. Add both before any mailing is sent.
6. **Residual advisories:** `zod@3` (concerns oversized array schemas; our schemas have no arrays) and the `postcss` copy Next pins internally (build-time only, our own CSS). Clear these with the zod 4 and Next 16 upgrades.
7. **Hot-linked gallery images** (Unsplash) are a production dependency on a third party. Self-host them, as already tracked in `docs/OPEN-QUESTIONS.md #4`.
8. **SQLite in production.** It is workable at this traffic, but the box already runs PostgreSQL, so switching is a settings change plus a data migration.
9. **Formatting and hooks:** 62 files fail `prettier --check`, and no `.husky/` directory exists, so the `lint-staged` hook never runs. Run one repo-wide `npm run format` commit, then add `format:check` to CI.
10. **e2e in CI:** add a job that starts both servers (with the raised throttle env vars) and runs Playwright.
11. **Content placeholders** in `docs/OPEN-QUESTIONS.md` (registration/VAT numbers, team, testimonials) remain business tasks.

## 4. Before the next deploy

No new environment variables are required. Check these:

- `backend/.env` has `DJANGO_DEBUG=false` and the long `DJANGO_SECRET_KEY` that `provision.sh` generated. Settings now **refuse to start** without them, which is intended.
- Django still binds to `127.0.0.1:8200`. The per-IP rate limits depend on it.
- After deploying, a sign-in with a wrong password should say "Incorrect username or password.", and two form submissions from different networks should not throttle each other.
